How to read. PHP banner: X-Powered-By PHP version vs
    the patched-release list shown above the result (kept server-side by the operator). Absent
    banners (CDN stripping, expose_php=Off) report unknown — a missing banner
    is not safety. Block test: an upload-style (multipart) request vs a normal form POST,
    on POST, PUT and PATCH — blocking POST alone is not enough, PHP 8.4 apps can read multipart
    on other methods too. ASSUMED VULNERABLE (red) means such requests flow through to
    the backend and no patched runtime could be confirmed — treat the site as vulnerable until
    a patched PHP version is verified. NO PHP
    DETECTED means no POST-shaped request is processed at this URL (connections dropped
    or 405/501 replies) and there are no PHP indicators (banner, session cookie) — consistent
    with a static site: nothing to exploit at this URL.

    
Probes. One URL at a time, eight inert requests (1 GET, then a normal +
    multipart request per method, plus a session-fixation probe that sends a random session id
    as a plain form field — never an upload-progress field, never a file part, so the vulnerable
    code path is never engaged). Redirects are followed like a browser (301/302/303 convert
    to GET, 307/308 keep the method, max 3 hops) — the first-hop status decides the
    verdict. A rejection at the CDN/WAF stops the request before PHP parses the body; the exact
    same status produced inside the application happens after — and the two cannot be
    told apart remotely, so the checker says so instead of over-claiming. A CDN-block also does
    not help if the origin server is directly reachable. A URL that refuses connections shows
    green OFFLINE — nothing is serving there, so there is nothing to assess.

    
Scope. This is a patch-status / configuration check, not a vulnerability
    probe: it never sends exploit-shaped requests (no session cookie, no file part, no
    upload-progress field, no stalling). Results live only in your browser session — there is no
    export endpoint; the tested URL stays in the address bar as ?url=… for
    bookmarking/sharing and is never sent anywhere. Every submission and every poll
    solves a small proof-of-work in your browser (an abuse brake, ~1s once per check).
    Definitive fix = a patched PHP runtime.

    
No guarantees. Results are best-effort indications from the outside:
    banners can lie, caches can hide the origin, and edge behavior differs per route. This is
    not a vulnerability assessment — verify on the host. Docs for humans and LLMs:
    llms.txt.
